# ADR-003: Review/Reputation을 AI 매칭 MVP 범위에서 제외

- 상태: 승인됨 (Accepted)
- 결정일: 2026-08-31
- 적용 범위: Review/Reputation, AI Matching 응답 및 Ranking

## 배경

초기 계획은 거래 완료 후 사용자 리뷰를 수집하고 Reputation 점수를 계산해 AI 매칭 Ranking에 반영하는 것이었다. 그러나 남은 기간에 발표 자료 준비, 프론트 연동, 거래 안정화와 성능 개선을 함께 완료해야 한다.

Review CRUD, 작성 권한, 거래별 중복 방지, 분석과 집계, Ranking 연동까지 구현하면 기능 수는 늘지만 각 흐름의 테스트와 완성도가 낮아질 위험이 크다.

## 결정

Review/Reputation을 이번 MVP에서 제외한다.

- Review 도메인과 AI Reputation 스켈레톤을 제거한다.
- `MatchCandidate.reputationScore` 예약 필드를 제거한다.
- Ranking은 의미 유사도와 명시적인 금액 적합도만 사용한다.
- 상태·카테고리·가격·예산·기간·마감일은 기존대로 SQL 원본에서 검증한다.
- Review/Reputation 재도입을 전제로 한 미사용 인터페이스나 중립 점수는 남기지 않는다.

```text
자연어 Query와 구조화 조건
→ Vector Search
→ SQL 원본 검증 및 필터링
→ semantic score + amount fit
→ TOP 3~5
→ 추천 이유 생성
```

## 결과

### 긍정적 영향

- 매칭 API와 응답 계약이 단순해진다.
- 미구현 기능에 대한 의존성과 통합 실패 가능성이 사라진다.
- 거래 안정화, 성능 개선, 프론트 연동과 발표 준비에 시간을 집중할 수 있다.
- 실제로 계산되지 않는 `null` 평판 점수를 프론트에 노출하지 않는다.

### 부정적 영향

- 사용자 신뢰도를 추천 순위에 반영하지 못한다.
- 거래 완료 후 사용자 피드백을 수집하는 기능이 없다.
- 추후 재도입 시 Review 정책과 Reputation 점수 계약을 새로 설계해야 한다.

## 재검토 조건

MVP 발표 이후 다음 조건이 충족되면 별도 ADR로 재도입을 검토한다.

- 거래 완료 흐름과 리뷰 작성 권한 정책이 확정됨
- 충분한 리뷰 데이터가 축적됨
- 평판 점수가 추천 품질을 개선한다는 검증 기준이 마련됨
